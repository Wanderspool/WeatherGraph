# Halo Exchange & Stitching

When running forecasts on massive global grids using [Spatial Tiling](spatial-tiling.md), the earth's surface is partitioned into separate tiles. Calculating forecasts for these tiles independently can introduce artificial boundaries or discontinuities (seams) at the partition interfaces.

To prevent this, WeatherGraph uses **overlapping halo exchanges** and **weighted stitching**. This guide explains the underlying blending mathematics and configuration options.

---

## 1. The Boundary Discontinuity Problem

Message-passing GNNs calculate predictions at a node by aggregating features from neighboring nodes. If the grid is split cleanly at a boundary, nodes near the border will lose their neighbors on the other side, causing calculation errors that accumulate at every autoregressive step:

```text
    Tile A (Active)            Tile B (Inactive)
    ┌─────────────┬───┐        ┌───┬─────────────┐
    │ Node        │ X │ < - - >│ Y │ Node        │
    │             │   │  Lost  │   │             │
    └─────────────┴───┘        └───┴─────────────┘
                  Boundary Interface
```

WeatherGraph solves this by adding an overlapping **halo region** (receptive field buffer) around each tile. 

---

## 2. Weighted Stitching Mathematics

When multiple tiles predict values for the same coordinate (the overlapping halo region), the C++ engine merges them. Rather than a simple average or hard cutoff, WeatherGraph implements a **weighted blending protocol**:

For each global node index $c$:

$$Y_g(c) = \frac{\sum_{t \in T_c} Y_t(c) \cdot W_t(c)}{\sum_{t \in T_c} W_t(c)}$$

Where:
*   $Y_g(c)$ is the final stitched global forecast tensor at coordinate $c$.
*   $T_c$ is the set of all tiles that contain node $c$ in their output coordinates.
*   $Y_t(c)$ is the forecast output tensor generated by tile $t$ for node $c$.
*   $W_t(c)$ is the blending weight of tile $t$ at node $c$ (ranging from $0.0$ to $1.0$).

---

## 3. Implementation in Python

This weighted aggregation is executed in-place during the tiled scatter phase in `weathergraph/model.py`:

```python
# Accumulate weighted output values
if "output_weights" in tile:
    weights = tile["output_weights"][np.newaxis, :, np.newaxis]
    output_buffer[:, tile["output_indices"], :] += tile_output * weights
    weight_buffer[:, tile["output_indices"], :] += weights
else:
    output_buffer[:, tile["output_indices"], :] += tile_output
    weight_buffer[:, tile["output_indices"], :] += 1.0

# Normalize by sum of weights
np.maximum(weight_buffer, 1e-8, out=weight_buffer)
output_buffer /= weight_buffer
```

### Weight Array Configurations
*   **Hard Boundaries** (No overlap): If no `output_weights_path` is specified in the manifest, the engine assumes $W_t(c) = 1.0$ for owned nodes, and requires that no two tiles share the same output indices.
*   **Soft Blending** (Cosine / Linear ramp): If `output_weights_path` is provided, weights are configured to decrease smoothly to $0.0$ near the edge of the tile, ensuring a seamless visual transition across partition boundaries.
